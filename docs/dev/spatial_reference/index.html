Spatial analysis settings and result keys

Lookup tables for the spatial pass of analyze and connectivity_analysis: configuration, thresholds, result keys, review-item codes, the decision ledger and the export bundle. For what the evidence means, see Spatial diagnostics and cleanup review; for the workflow, see the spatial cleanup tutorial.

Configuration: [spatial]

Set keys in a TOML file passed as config=load_config("file.toml"), or edit load_config()["spatial"] before calling analyze(net; config=config). Omitted keys keep their defaults (from config/default.toml).

KeyDefaultValid valuesControls
enabledtrueBooleanThe whole pass. false skips coordinate inventory, routes, proximity, candidates and review capture; no W.GEO.* Findings.
proximity_enabledtrueBooleanProximity inventory (proximity).
proximity_radius_m1.0finite, > 0Neighbor radius for proximity and S.NEARBY_WITHOUT_DIRECT_BRANCH.
max_candidate_pairs1000000integer ≥ 1Location-pair budget for the proximity search.
witness_limit20integer ≥ 1Examples kept per proximity and candidate check (and members per cluster).
discrepancy_enabledtrueBooleanThe S.* candidate checks (discrepancy_candidates).
max_topology_pairs100000integer ≥ 1Budget for nearby-pair expansion, series-path steps, branch-span pairs, route-segment processing and route-endpoint bus queries.
max_series_hops8integer 2–64Longest line-only series path (edges) compared with a direct line.
route_endpoint_tolerance_m5.0finite, > 0Route-endpoint candidate tolerance and alternative-bus search radius; also the absolute floor of the series-path detour rule.
long_span_threshold_m10000.0finite, > 0Absolute span above which a branch or route segment becomes a candidate.

Invalid values make the affected part indeterminate with reason invalid_configuration; a disabled part is inapplicable with reason disabled. A non-Boolean enabled or a non-object [spatial] section makes the whole pass indeterminate / invalid_configuration.

Outside Julia, the pass is turned off with execute_analysis(net; spatial_enabled=false), bin/bmopf analyze-case --input CASE.json --no-spatial or the MCP bmopf_analyze argument "spatial_enabled": false; the response records the effective value. See JSON execution.

Thresholds

Distances are great-circle lengths (sphere radius 6 371 008.8 m) in a geographic frame and Euclidean lengths in a declared local Cartesian frame. "Comparison length" is line.meta.physical_length_m when that key is present, otherwise the declared line.length unless meta.electrical_length_regularized = true (then unavailable). Only route_endpoint_tolerance_m, long_span_threshold_m and proximity_radius_m are configurable.

The route endpoint gap is min over the two orientations of the larger of the two endpoint distances. Unit factors for the length-scale rule are 0.001 (km stored as m), 1000, 1/0.3048 (ft stored as m), 0.3048 (coordinates in ft declared as m), 1/304.8 (kft) and 1/1609.344 (mi). W.GEO.* Findings fire only with a declared network frame; route evidence alone supports measurements but no Finding. Placeholder lengths (exactly 1 on a line with inline impedance totals) are not compared. The Finding definitions are in the GEO reference.

Candidate checks and S.* codes

Each entry of discrepancy_candidates.checks has status, reason, scope, counts_complete, n_candidates (null when incomplete), n_candidates_observed (lower bound), witnesses (≤ witness_limit) and check-specific domain counts (n_*). S.* codes label review candidates; they are not Finding codes.

CheckCodeEvidence
nearby_topologyS.NEARBY_WITHOUT_DIRECT_BRANCHMetric-eligible bus pair within the proximity radius (including co-location) with no direct line, switch or supported transformer between them; carries component_relation (same_bus_component, separate_bus_components, unknown_switch_state, indeterminate_graph), voltage_tier_relation (same, different, unknown) and endpoint_like.
series_pathsS.DIRECT_ALONGSIDE_SERIES_PATHA direct line and a line-only path of 2 to max_series_hops edges with degree-two interior buses, meeting the detour rule above.
branch_spansS.LONG_BRANCH_SPANLine, switch or all-winding transformer span above long_span_threshold_m.
route_endpointsS.ROUTE_ENDPOINT_DISAGREEMENTValid WGS84 route whose endpoints disagree with eligible WGS84 bus positions; orientation (forward, reversed, ambiguous), per-side gap_m, unassigned nearby_alternative_buses.
route_overlapsS.SHARED_ROUTE_SEGMENTTwo or more lines with exactly the same nonzero WGS84 vertex-to-vertex segment, either direction.
source_intervalsS.REPEATED_SOURCE_INTERVALAn explicit nonempty string repeated in meta.source_interval, or separately in meta.backbone_extension.source_interval.
route_defectsS.INVALID_ROUTE_GEOMETRY, S.ROUTE_SEGMENT_DEFECTMalformed route data; zero-length or repeated undirected WGS84 segments, or segments above long_span_threshold_m.

Shared-segment and repeated-source groups also carry declared_arrangement (series_chain, parallel_bus_pair, branched_or_cyclic, disconnected, indeterminate), terminal_map_relation (equal_declared_maps, different_declared_maps, unassessed) and a voltage_context computed over all members, whose relation is same, different, crossing_endpoint_tiers or unknown. Unassessed: partial collinear overlap, crossings, self-intersections without a repeated segment, arbitrary alternate paths, electrical equivalence.

R.LINE_LENGTH_CONTEXT

One review item per line whose length_context carries any tag other than regularized_electrical_length. Tags: shorter_than_chord, far_longer_than_chord, stored_route_length_mismatch, physical_route_length_mismatch, declared_physical_length_mismatch, invalid_route_geometry, invalid_route_length, invalid_length_declaration, regularized_electrical_length. The item evidence keeps all lengths, the comparison basis, thresholds, length_scales_impedance and source references (raw_key, raw_layer, source_entity_id).

Sidecar dispositions

Decision records are created by spatial_review_decision and replayed by apply_spatial_review. Ledger file envelope:

{"schema_version": "spatial-cleanup-review/v1", "decisions": [ ... ]}

Record fields (exactly these keys):

FieldRequirement
schema_versionspatial-cleanup-review/v1
item_idNonempty; must match one captured item when created.
case_fingerprint, analysis_fingerprint, evidence_fingerprint64-character lowercase hex, copied from the review.

Fingerprints (canonical SHA-256: sorted object keys, integral floats written as integers):

FingerprintHashes
case_fingerprintThe whole network dictionary, except _meta.parsed_at and meta.provenance.parsed_at. Not the input file hash.
analysis_fingerprintspatial-cleanup-review/v1, spatial-review-priority/v2 and the whole [spatial] section.
evidence_fingerprintThe item's identity, code, check, evidence, location, geometry, coverage, impact, priority, ranking reason, evidence class, subjects, assessment, coordinate evidence and interpretation evidence.

Replay rules: the latest recorded_at per item wins; identical duplicates are harmless; records for absent items are kept as unmatched; each replay starts from unreviewed, so an empty ledger resets all dispositions. decision_audit holds records, invalid_records (with issues), unmatched_records, n_invalid_records, n_unmatched_records and policy. A review with duplicate item IDs must be regenerated before replay.

Export bundle

export_spatial_review(review, outdir; item_limit=20) writes:

FileContents
review.mdrender_spatial_review output: coverage banner, category and disposition counts, candidate index, attention items grouped by location, expandable context and reviewed inventories.
review.jsonThe complete captured queue (or the replayed copy).
review.geojsonspatial_review_geojson output.
decisions-template.jsonEmpty ledger envelope; an existing file is preserved.

Other files are replaced. item_limit (nonnegative integer) caps each of the attention, context and reviewed sections separately in Markdown; it does not change the captured queue. render(report, "report.md") includes the same section with a cap of 20.

spatial_review_geojson returns a FeatureCollection of WGS84 MultiPoint features, one per located item, with review_schema_version, queue_complete, scope, coordinate_context and n_items_without_wgs84_geometry. Feature properties carry the item's code, location, priority, ranking reason, impact, subjects, review state, geometry basis and coverage, fingerprints, assessment and evidence. Cartesian and unlocated items are omitted and counted.

Command-line example:

julia --project=. examples/spatial_cleanup_review.jl CASE.json OUTDIR [DECISIONS.json]

The JSON execution interface's analyze_case returns the unreviewed queue in the report; disposition replay and GeoJSON export are Julia-only.
