Profile your first messy case

Run the profiler on a small feeder with six planted defects, read what it says, decide what each finding means, repair what is wrong, and check again.

This is the loop every case goes through: run → read → understand → decide → recheck. The feeder is small enough that you can see the whole of it, and every block on this page is executed when the documentation is built, so the output you see is what the code produces.

Prerequisites

Only BMOPFTools. No solver is needed.

1. A clean case, and what clean looks like

The starting point is a bundled European-style feeder: a 10 kV / 400 V delta-wye substation whose star point is earthed at the transformer, and a four-wire LV feeder with three single-phase customers and one three-phase customer.

using BMOPFTools

fixture = joinpath(pkgdir(BMOPFTools), "test", "data", "profiler_systems",
                   "eu_tn_four_wire.json")
clean = parse_bmopf(fixture)
report = analyze(clean)
println(length(errors(report)), " errors, ", length(warnings(report)), " warnings, ",
        length(infos(report)), " infos")
0 errors, 0 warnings, 8 infos

No errors and no warnings. The infos are worth a glance even on a clean case, because they state what the profiler understood:

for f in infos(report)
    println(rpad(f.code, 28), first(f.message, 90))
end
I.DIV.LOAD_UNIFORM_MODEL    All 4 loads use the constant_power model — no load exercises voltage dependence (ZIP/expon
I.PROV.SEQ_DERIVED          1 linecode(s) have a balanced phase block and an explicit extra conductor. Sequence input
I.PROV.LINE_MODEL_UNIFORM   All 1 line-model definition(s) use a single, consistent model: pure series impedance. Shun
I.PRE.XFMR_COIL_UNASSESSED  Transformer 'sub' nominal coil headroom is unassessed: unsupported_transformer_subtype.
I.PRE.NO_VOLT_BOUNDS        4 bus(es) have no voltage magnitude bounds — voltage will be unconstrained at these buses.
I.PRE.SINGLE_SOURCE         Network has a single voltage source — single point of failure. Infeasibility of the source
I.SCHEMA.VERSION_UNKNOWN    Spec version 'unknown' has no bundled JSON Schema; structural validation skipped. Unknown-
I.BENCH.AUGMENTATION        Case needs augmentation to be a non-trivial OPF benchmark: no priced slack or generator —

An INFO is context, not a defect. I.PRE.NO_VOLT_BOUNDS says the case has no voltage limits yet, which is true and expected before augmentation. I.SCHEMA.VERSION_UNKNOWN appears because the fixture carries no meta["$schema"] URI, so the JSON Schema layer is skipped and only the field catalog runs; I.PRE.XFMR_COIL_UNASSESSED appears because the coil-headroom screen estimates only single-phase transformer banks, and this substation is a three-phase delta_wye unit. Nothing here asks you to change the data.

2. The messy case

Real data rarely arrives like that. The next block plants six defects of the kinds that conversions, exports and hand edits produce. Read the comments: you will meet each one again in the report.

net = deepcopy(clean)

# 1. The export lost the star-point earth of the transformer.
delete!(net["bus"]["lv0"], "perfectly_grounded_terminals")
# 2. One line length was typed in kilometers (0.15) instead of meters (150).
net["line"]["f2"]["length"] = 0.15
# 3. Conductor ratings were never exported.
delete!(net["linecode"]["cable"], "i_max")
# 4. A reactive power was entered in the wrong unit: power factor 0.4.
net["load"]["h3"]["q_nom"] = [9000.0]
# 5. A spur to a bus with nothing on it, left over from a removed customer.
net["bus"]["stub"] = Dict{String,Any}("terminal_names" => ["a", "b", "c", "n"])
net["line"]["spur"] = Dict{String,Any}("bus_from" => "lv1", "bus_to" => "stub",
    "terminal_map_from" => ["a", "b", "c", "n"], "terminal_map_to" => ["a", "b", "c", "n"],
    "linecode" => "cable", "length" => 40.0)
# 6. A terminal name typo on the three-phase customer: "m" instead of "n".
net["load"]["shop"]["terminal_map"] = ["a", "b", "c", "m"]

3. Run and read

report = analyze(net)
println(length(errors(report)), " errors, ", length(warnings(report)), " warnings, ",
        length(infos(report)), " infos")
2 errors, 5 warnings, 11 infos

Read the errors first. An ERROR means the case cannot give a trustworthy answer as it stands.

for f in errors(report)
    println(f.code, "  [", something(f.component_id, "network"), "]")
    println("    ", f.message)
end
E.PROV.FLOATING_NEUTRAL  [network]
    Neutral section spanning 4 bus(es) has no path to ground and is used by loads/generators — the zero-sequence path is undefined (ill-posed for 4-wire analysis) : lv0, lv1, lv2, stub.
E.INT.UNKNOWN_TERMINAL  [shop]
    load 'shop' terminal_map references terminal(s) ["m"] not defined at bus 'lv2'.

Then the warnings: data that is suspicious or that degrades the result.

for f in warnings(report)
    println(f.code, "  [", something(f.component_id, "network"), "]")
    println("    ", first(f.message, 150))
end
W.CONN.DANGLING  [network]
    1 bus(es) are degree-1 with no attached load, generator, shunt, capacitor, ibr, or source.
W.PROV.I_MAX_ABSENT  [network]
    3 line(s) have no `i_max` or `s_max` on the line or its linecode (or no linecode at all) — their series current is left entirely unconstrained in the
W.DOM.LOAD_PF_LOW  [h3]
    Load 'h3' has power factor 0.406 < 0.7.

    load 'shop': device indexing cannot be assessed.
W.INT.FLOATING_LOAD_TERMINAL  [shop]
    load 'shop' at bus 'lv2' has phase terminal(s) ["m"] that are not wired by any branch — the voltage at those terminals is decoupled from the network (

Always match on f.code. The message is written for people and may be reworded; the code is a stable identifier.

4. Understand a finding before acting on it

Each code has a catalog entry you can look up offline:

entry = explain_finding("E.PROV.FLOATING_NEUTRAL")
println(entry["severity"], " — ", entry["section_title"])
println(entry["meaning"])
ERROR — provenance & conventions
A neutral section (continuity graph over lines/closed switches) with no path to ground (perfect grounding, a grounding shunt, a source that references the neutral, or a transformer neutral impedance) **and** loads/generators using it — the zero-sequence path is undefined; 4-wire analysis is ill-posed.

The instance itself carries the evidence. For the floating neutral, the detail names the buses of the affected neutral section:

floating = only(f for f in report.findings if f.code == "E.PROV.FLOATING_NEUTRAL")
println(floating.detail["buses"])
["lv0", "lv1", "lv2", "stub"]

Why does a floating neutral matter? The neutral conductor connects the four LV buses to each other, but nothing connects it to earth, and the delta-wye transformer gives the LV side no galvanic path to the earthed source. The load return currents then have no defined path to earth: the zero-sequence path is undefined, and a four-wire analysis of the LV island is ill-posed. On its own, the lost earth would also leave the LV island without any voltage reference (E.INT.NO_VOLTAGE_REFERENCE: voltages defined only up to a common shift). That error is absent here only by accident: because m is not a neutral, the profiler reads the shop load as connected from each phase to earth, and that typo is the island's only tie to earth. Two defects mask each other, which is another reason to fix by cause. The profiler even points at where the earth should have been:

hint = only(f for f in report.findings if f.code == "I.PROV.WYE_NEUTRAL_UNGROUNDED")
println(hint.message)
Transformer 'sub' (delta_wye) brings out a three-phase wye neutral on its secondary side at bus 'lv0', but that bus has no local grounding (no perfect ground and no grounding impedance). The star point's zero-sequence potential is set only by what the neutral conductor reaches elsewhere — add a grounding shunt or perfect ground at 'lv0' if a local earth was intended.

That is an INFO, and it is the most useful line in the report: it names the transformer star point that has no earth. Severity tells you how bad the consequence is, not how helpful the finding is. The physics of each grounding finding, with a case where it is right and a case where it is harmless, is in Grounding and neutral findings explained.

5. Decide

Sort every warning and error into one of three piles: fix, decide, disclose.

FindingPileWhy
E.PROV.FLOATING_NEUTRALfixone defect: the lost star-point earth
E.INT.UNKNOWN_TERMINAL, W.INT.FLOATING_LOAD_TERMINAL, W.INT.DEVICE_INDEXING_UNASSESSED on shopfixone defect: the terminal typo
W.DOM.LOAD_PF_LOW on h3fixa power factor of 0.4 on a household is a unit error
W.PROV.I_MAX_ABSENTfix, or discloseratings are missing; restore them from the source, or state that thermal limits are not enforced
W.CONN.DANGLINGdecidethe spur carries nothing; remove it, or keep it and say so

Seven warnings and errors, four defects to repair and one judgment call. Several findings share a cause, which is why you sort by cause before touching the data.

One defect produced no warning at all: the line length typed in kilometers. It is in the infos:

for f in report.findings
    f.code == "I.PROV.LINE_SWITCH_LIKE" && println(f.component_id, ": ", f.message)
end
f2: Line 'f2' has near-zero series impedance and may be modeled more accurately as a switch: effective impedance (Z·length) < 0.0001 Ω on all diagonals.

A 15 cm line is electrically almost a short circuit, so the profiler notes that it looks like a switch. It cannot know that the length is wrong: short jumpers exist. This is the kind of finding that needs you. If the case had coordinates, the spatial checks would compare the length with the distance between the buses and settle it.

6. Repair and recheck

Fix what is wrong at the source of the error, not by silencing the finding.

fixed = deepcopy(net)
fixed["bus"]["lv0"]["perfectly_grounded_terminals"] = ["n"]        # the star-point earth
fixed["load"]["shop"]["terminal_map"] = ["a", "b", "c", "n"]      # the typo
fixed["load"]["h3"]["q_nom"] = [1300.0]                           # 4 kW at pf 0.95
fixed["linecode"]["cable"]["i_max"] = fill(250.0, 4)              # ratings from the source
fixed["line"]["f2"]["length"] = 150.0                             # meters
delete!(fixed["line"], "spur"); delete!(fixed["bus"], "stub")     # decision: remove the spur

after = analyze(fixed)
println(length(errors(after)), " errors, ", length(warnings(after)), " warnings")
0 errors, 0 warnings

Recheck by comparing codes, not by counting. A repair can remove findings and can also introduce new ones:

before_codes = Set(f.code for f in report.findings)
after_codes = Set(f.code for f in after.findings)
println("cleared   : ", sort(collect(setdiff(before_codes, after_codes))))
println("introduced: ", sort(collect(setdiff(after_codes, before_codes))))
cleared   : ["E.INT.UNKNOWN_TERMINAL", "E.PROV.FLOATING_NEUTRAL", "I.PROV.LINE_SWITCH_LIKE", "I.PROV.WYE_NEUTRAL_UNGROUNDED", "I.TMAP.PERMUTED_ORDER", "W.CONN.DANGLING", "W.DOM.LOAD_PF_LOW", "W.INT.DEVICE_INDEXING_UNASSESSED", "W.INT.FLOATING_LOAD_TERMINAL", "W.PROV.I_MAX_ABSENT"]
introduced: String[]

Nothing was introduced, and every code that came from a planted defect is gone, including I.TMAP.PERMUTED_ORDER, which the terminal typo on shop produced. The repaired case is the clean case again.

7. Keep the report

Write the report next to the case, so the next reader sees what was checked:

render(after, "messy-case-after.md")
println(first(readlines("messy-case-after.md"), 6) |> x -> join(x, "\n"))
# BMOPF Network Summary: eu_tn_four_wire

**Generated:** 2026-11-28 01:43:40
**Findings:** 0 errors · 0 warnings · 8 info
**Convention:** MV_5.8kV: no branch conductors represented; LV_231V: 4-wire; 1 grounding point(s); series-only line model

What to take away

  • Errors first, then warnings, then read the infos. The most informative line can be an INFO.
  • Sort by root cause. Several findings usually share one.
  • Three piles: fix, decide, disclose. A finding you decide to live with is recorded, not hidden: see Accept and track findings.
  • Recheck by diffing codes. A clean count can hide a new finding.
