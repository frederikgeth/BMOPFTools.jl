Tune profiler thresholds

Several checks compare a value with a threshold: a minimum power factor, a feeder length that looks implausible, the impedance below which a line looks like a switch. The defaults are order-of-magnitude norms, not standards. This page shows how to change one, and lists every threshold with the finding it drives.

Change a threshold for one study

Load the defaults, change what you need, and pass the result to analyze:

using BMOPFTools

fixture = joinpath(pkgdir(BMOPFTools), "test", "data", "profiler_systems",
                   "eu_tn_four_wire.json")
net = parse_bmopf(fixture)
net["load"]["h3"]["q_nom"] = [3000.0]          # 4 kW at power factor 0.8

cfg = load_config()
println("default pf_min: ", cfg["domain_rules"]["pf_min"])
println("default : ", [f.code for f in warnings(analyze(net))])

cfg["domain_rules"]["pf_min"] = 0.85           # a stricter house rule
println("stricter: ", [f.code for f in warnings(analyze(net; config = cfg))])
default pf_min: 0.7
default : String[]
stricter: ["W.DOM.LOAD_PF_LOW"]

Keep the thresholds in a file

For a rule that applies to every case of a utility or a project, write a TOML file that contains only the keys you change. It is merged over the packaged defaults:

write("house_rules.toml", """
[domain_rules]
pf_min = 0.85

[operational.feeder_length.LV]
reach_long_m = 600.0
""")
cfg = load_config("house_rules.toml")
println(cfg["domain_rules"]["pf_min"], "  ", cfg["operational"]["feeder_length"]["LV"]["reach_long_m"],
        "  ", cfg["domain_rules"]["xfmr_ratio_max"], " (unchanged default)")
0.85  600.0  1000.0 (unchanged default)

Keep that file with the cases it was used on. A report is only reproducible together with the thresholds that produced it.

The packaged defaults are in config/default.toml, with the reasoning for each value in the comments. All of the sections below follow the config passed to analyze.

[operational.feeder_length.<band>]

One table per voltage band (LV below 1 kV, MV 1–35 kV, HV 35–100 kV, EHV above), applied to the per-conductor nominal voltage.

KeyDefaults (LV / MV / HV / EHV)Finding
reach_short_m30 / 200 / 0 / 0I.OPS.FEEDER_SHORT when a zone's electrical reach is below this; 0 disables
reach_long_m1000 / 20000 / 100000 / 300000I.OPS.FEEDER_LONG above this; 0 disables

These are the thresholds most worth adapting to a region. A North American rural 12.47 kV feeder, or an Australian SWER line, runs well beyond 20 km, and a service drop is legitimately shorter than 30 m:

[operational.feeder_length.MV]
reach_long_m = 60000.0      # long rural feeders are normal here

[operational.feeder_length.LV]
reach_short_m = 0.0         # do not report service drops

The feeder-length reference explains how reach is measured and the separate multi_boundary policy.

[provenance.dss_defaults]

Values that OpenDSS substitutes when a field is missing. A match means the value probably came from the tool, not from data.

The length tolerances of the W.GEO.* Findings (max(5 m, 10 %) for a line shorter than its chord, max(5 × chord, chord + 100 m) for one far longer) are fixed. See Spatial diagnostics.

Not used by analyze

[thermal] and [augment.*] configure augment_case and the IBR presets. [provenance.grounding] is kept so that old configuration files still load; its two keys no longer affect any report.

Thresholds that are fixed in the code

Some checks use a fixed value because changing it would change what the finding means: the 5 % tolerance for a voltage-level mismatch, the 5 % of load below which local generation is negligible, the 90 % transformer loading mark. They are stated in the finding-code reference entry of each code. If one of them does not fit your network, the right response is to record a decision about that finding, not to move the threshold: see Accept and track findings.
