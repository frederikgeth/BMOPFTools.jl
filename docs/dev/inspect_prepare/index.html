Inspect and prepare cases

An imported distribution model is rarely ready to optimize. It can be electrically inconsistent (a floating neutral, a terminal typo), silent about what a study needs (no ratings, no voltage bounds, no costs), or larger than the study requires. This section covers the three steps between a raw import and a case you can solve and defend:

  1. Profile: run analyze, read the findings, and decide for each one whether to fix the data, record a judgment, or disclose a limitation.
  2. Prepare: repair the structure, place DERs, and add the study assumptions (bounds, ratings, costs) with a manifest that records where every value came from.
  3. Reduce (optional): remove buses or conductors the study does not need, and know what each reduction preserves.

Profiling comes first and again last: every transformation in steps 2 and 3 changes the case, so the profiler runs again on the result.

The pages are grouped by role. Tutorials walk through one case from start to finish. How-to pages answer one task. Explanation pages give the physics and the reasoning behind the checks. Reference pages list every key, setting and pass. Finding codes are listed in the finding-code reference.

Which pages run when the documentation is built

The profiling tutorials, the grounding explanation, the two how-to pages and the transformer test-report tutorial execute every block at build time, on fixtures that ship with the package: the output shown is what the current code produces.

Five pages use a CC BY-NC-SA utility dataset that is not bundled (set ENV["BMOPF_RESTRICTED_DATA"] to run them): the triage case study, the end-to-end tutorial, the provenance tutorial, the DER tutorial and the simplification tutorial. Their code is shown but not executed by the build, so read their printed values as illustrative. The reduction pages quote numbers from example scripts under examples/opti_kron/ and scripts/, which name their own requirements.
